# 11 — Roadmap

## Roadmap principle

Advance only after real signals.

Do not build SaaS infrastructure before the utility site proves demand.

## V0 — MVP utility site

### Condition to enter

Current phase.

### Features allowed

- Home scanner.
- SPF check.
- DMARC check.
- MX check.
- SPF DNS lookup count.
- Basic Gmail/Yahoo readiness.
- Score.
- Next steps.
- Setup assistance CTA.
- First 5 SEO pages.

### Features prohibited

- login;
- dashboard;
- billing;
- database;
- monitoring;
- API monetization;
- agency panel.

### Risk

The tool may be too simple to stand out.

## V1 — Hub SEO

### Condition to advance

Advance if MVP pages are indexed and users are scanning domains.

Suggested signals:

- 100+ scans;
- growing Search Console impressions;
- positive feedback on result clarity.

### Features allowed

- DKIM selector checker.
- Gmail/Yahoo sender requirements checker.
- Google Workspace guide.
- Microsoft 365 guide.
- Mailchimp/Brevo/SendGrid guides.
- Better internal linking.
- FAQ improvements.

### Features prohibited

- recurring monitoring;
- paid plans;
- dashboard;
- database-heavy features.

### Risk

Creating generic SEO content that does not rank or convert.

## V2 — Lead capture/setup

### Condition to advance

Advance if users click CTAs or ask for help.

Suggested signals:

- 5+ email captures;
- 1+ setup request;
- users ask how to fix records.

### Features allowed

- better lead form;
- email checklist;
- “copy technical report”;
- “send this to my developer” flow;
- manual setup service page;
- simple pricing experiment for assisted setup, if validated.

### Features prohibited

- automatic billing platform;
- subscription plans;
- client dashboard;
- agency multi-tenant workflows.

### Risk

Manual service can become time-consuming before revenue is clear.

## V3 — Simple monitoring

### Condition to advance

Advance only if users explicitly request recurring checks.

Suggested signals:

- repeated requests for monitoring;
- agencies asking to watch client domains;
- users returning to rescan the same domain.

### Features allowed

- simple domain monitoring pilot;
- daily/weekly check;
- email alert when records change or break;
- minimal persistence if absolutely required;
- manual early access.

### Features prohibited

- full SaaS dashboard;
- complex team accounts;
- role permissions;
- advanced billing;
- agency panel.

### Risk

Monitoring introduces database, scheduling, email delivery and support complexity.

## V4 — SaaS / agency / API

### Condition to advance

Advance only if there is clear commercial demand.

Suggested signals:

- agencies ask for multiple domains;
- users ask for API access;
- monitoring pilot has paying users;
- setup assistance converts into paid work.

### Features allowed

- accounts;
- multiple domains;
- history;
- monitoring;
- agency workspace;
- public API;
- billing;
- reports.

### Features prohibited

- enterprise features without customers;
- complex compliance workflows;
- broad deliverability platform positioning;
- competing directly with mature enterprise tools too early.

### Risk

Competing with established deliverability platforms before having distribution.
